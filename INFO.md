# `Statement#setMaxRows`

`setMaxRows(int max)` - метод JDBC-интерфейса `Statement`, который задает максимальное количество строк, доступных в любом `ResultSet`, полученном этим `Statement`.

В примере `FindAllUsers_setMaxRows.java`:

```java
s.setMaxRows(MAX_ROWS);
try (ResultSet rs = s.executeQuery(QUERY)) {
    ...
}
```

значение `MAX_ROWS` равно `10`, поэтому результат запроса будет ограничен максимум десятью строками.

## Для чего используется

Метод нужен, когда приложение хочет защититься от слишком большого результата запроса или показать только ограниченное число записей. Например:

- вывести первые несколько строк для демонстрации;
- ограничить объем данных, читаемых из `ResultSet`;
- снизить риск случайной загрузки большого набора строк в память.

## Как работает

Ограничение задается на уровне JDBC `Statement`, а не внутри SQL-запроса. После вызова `setMaxRows(10)` все последующие запросы, выполненные через этот объект `Statement`, возвращают `ResultSet` не больше чем из десяти строк.

Если запрос фактически находит больше строк, лишние строки не попадают в результирующий набор. Ошибка при этом не возникает.

Значение `0` снимает ограничение:

```java
s.setMaxRows(0);
```

Отрицательное значение запрещено и приводит к `SQLException`.

## Важные нюансы

`setMaxRows` не заменяет SQL-пагинацию через `LIMIT` и `OFFSET`. Для настоящей постраничной выборки лучше явно писать ограничение в SQL:

```sql
SELECT user_id, username, email, created_at
FROM users
ORDER BY user_id
LIMIT 10 OFFSET 0
```

Также в исходном запросе из примера нет `ORDER BY`, поэтому база данных не обязана возвращать строки в стабильном порядке. Метод ограничит количество строк, но не гарантирует, какие именно десять пользователей попадут в результат.

# `Statement#setFetchSize`

`setFetchSize(int rows)` - метод JDBC-интерфейса `Statement`, который задает драйверу подсказку, сколько строк стоит получать из базы данных за один раз при чтении `ResultSet`.

В примере `FindAllUsers_setFetchSize.java`:

```java
s.setFetchSize(FETCH_SIZE);
try (ResultSet rs = s.executeQuery(QUERY)) {
    ...
}
```

значение `FETCH_SIZE` равно `10`, поэтому код просит JDBC-драйвер читать строки из результата небольшими порциями по десять записей.

## Для чего используется

Метод нужен, когда результат запроса может быть большим и приложение не хочет сразу получать все строки одним крупным блоком. Например:

- читать большой `ResultSet` более ровными порциями;
- снизить пиковое потребление памяти на стороне клиента;
- управлять сетевым обменом между приложением и базой данных;
- показать отличие размера выборки из драйвера от ограничения количества строк.

## Как работает

`setFetchSize` не ограничивает итоговое количество строк в результате. Он только сообщает драйверу желаемый размер порции чтения.

После вызова `setFetchSize(10)` запрос по-прежнему может вернуть 42, 1000 или больше строк, если они есть в таблице. Приложение продолжит обходить весь `ResultSet`, но драйвер может получать данные из базы частями.

Значение `0` означает поведение драйвера по умолчанию:

```java
s.setFetchSize(0);
```

Отрицательное значение запрещено и приводит к `SQLException`.

## Важные нюансы

`setFetchSize` - это подсказка драйверу, а не строгая команда базе данных. Конкретное поведение зависит от JDBC-драйвера и настроек соединения.

Главное отличие от `setMaxRows`: `setMaxRows(10)` ограничивает результат максимум десятью строками, а `setFetchSize(10)` не уменьшает результат, а только влияет на то, какими порциями драйвер может читать строки.

Для PostgreSQL streaming через server-side cursor обычно требует отключенного autocommit на соединении. Если autocommit включен, драйвер может прочитать результат сразу, даже если задан `fetchSize`. В учебных примерах метод показывается как JDBC-настройка `Statement`; для production-кода важно дополнительно учитывать настройки транзакции, драйвера и размер результата.

# `Statement#setQueryTimeout`

`setQueryTimeout(int seconds)` - метод JDBC-интерфейса `Statement`, который задает максимальное время выполнения SQL-запроса в секундах.

В примере `FindAllUsers_setQueryTimeout.java`:

```java
s.setQueryTimeout(QUERY_TIMEOUT_SEC);
try (ResultSet rs = s.executeQuery(QUERY)) {
    ...
}
```

значение `QUERY_TIMEOUT_SEC` равно `1`, поэтому JDBC-драйвер должен попытаться отменить запрос, если он выполняется дольше одной секунды.

## Для чего используется

Метод нужен, когда приложение не должно бесконечно ждать медленный или зависший SQL-запрос. Например:

- ограничить время ожидания ответа от базы данных;
- защитить приложение от слишком долгих запросов;
- быстрее вернуть ошибку пользователю или вызывающему коду;
- не держать поток приложения занятым дольше заданного лимита.

## Как работает

Ограничение задается на уровне JDBC `Statement`. После вызова `setQueryTimeout(1)` все последующие запросы, выполненные через этот объект `Statement`, получают таймаут в одну секунду.

Если запрос укладывается в лимит, он выполняется как обычно и возвращает `ResultSet`.

Если запрос превышает лимит, JDBC-драйвер пытается отменить выполнение запроса. В этом случае `executeQuery`, `executeUpdate` или другой метод выполнения запроса может завершиться с `SQLException`.

Значение `0` снимает ограничение:

```java
s.setQueryTimeout(0);
```

Отрицательное значение запрещено и приводит к `SQLException`.

## Важные нюансы

`setQueryTimeout` задает лимит в секундах, а не в миллисекундах.

Точное поведение зависит от JDBC-драйвера и базы данных. Метод сообщает драйверу, что запрос нужно ограничить по времени, но механизм отмены реализует конкретный драйвер.

Для PostgreSQL есть похожая серверная настройка `statement_timeout`. Она задается на стороне базы данных, а `setQueryTimeout` задается из Java-кода через JDBC. В учебном примере используется именно JDBC-подход.

`setQueryTimeout` не ускоряет запрос сам по себе. Он только ограничивает максимальное время ожидания и помогает не зависать на долгих операциях.
